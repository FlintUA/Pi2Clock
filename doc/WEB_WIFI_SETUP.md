## User workflow

From the home page, use Connect directly, join SpeakingClock with its saved password, and reopen 192.168.4.1 with a remembered Direct browser permission. Close physical editors and stop timers/music before starting setup. Home networks is open by default and shows both saved networks with separate Connect and Edit actions. Use Connect directly in the Connection block to edit them. Browser access is a separate collapsed disclosure. Editing, testing and forgetting are available in Direct. Longer instructions are collapsed into help disclosures.

Choose Edit (or Add for an empty slot) beside Main or Backup to open its editor. In Home, Edit explains Direct and offers Connect directly to edit, plus Close. In Direct, the editor opens immediately. Use Find networks and select a result, or enter a name manually for a hidden network. Enter its password, using Show/Hide if needed, or explicitly choose Open network. Only the newly entered password can be shown; saved passwords are never returned. Profile/result changes and submitted attempts clear the field; leaving the page in the background masks it. Connect and save asks for confirmation before the connection ends. There is a five-second grace period with Cancel connection. The clock then leaves Direct and allows up to 45 seconds to join the candidate and obtain an IPv4 address. This is an association/address test, not an Internet or NTP test. The other profile is retained. The same SSID cannot occupy both slots. Confirmed Forget network (under Remove this saved network) removes only the selected profile. Combined AP/STA mode and browser credential clearing are not added.

On success, join the candidate home network on the phone and read the new address in the physical Phone Control status page. The firmware accepts the candidate for normal deferred settings autosave only after a new join attempt has reached link/IP ready and the web service has an address. Keep power connected until Settings saved appears. The protocol state saved means accepted for autosave, not proof that Flash has completed; the existing root saving state distinguishes pending/retry/saved. If the tested credentials are identical to the saved ones, no settings write or home-trust change is needed.

On timeout/cancellation, old saved credentials are reconfigured and Direct restarts with its existing key. Reconnect to SpeakingClock and read the result; the source page retains its handoff instructions and does not redirect. A failed test never copies the candidate into the saved configuration. If audio, a timer, a player or an editor becomes active during testing, recovery waits for it to become idle rather than interrupting it. The read-only Phone Control menu remains allowed so it can show progress/IP; its mode/access/key-changing actions are blocked while a trial is active. Old settings remain recoverable by restarting even while recovery is waiting. If Direct restart itself fails, the old home configuration remains selected and the page/LCD/USB are the recovery routes; restarting uses the old saved configuration. The temporary home-trust suspension remains in effect until Direct or a fresh old-home connection is available.

The Cancel action cannot undo a candidate already accepted after successful connection. A completed selection or a closed browser is not a cancellation request. Reboot before candidate acceptance uses the old saved settings; reboot after acceptance but before a successful autosave can also use the old Flash record. Save/power-cycle behavior still needs physical testing.

## Authorization and secret handling

The same existing token, scope, Host/Origin, epoch, command-ID/nonce, serialization and retry checks apply. Testing is admitted only from Direct, with idle audio/closed editors and no Bluetooth inquiry or pending mode switch. A second test conflicts with an active trial. Wi-Fi USB configure/clear and physical mode/access/key changes are blocked during the transaction; ordinary audio priorities retain their behavior. A browser permission removal cancels a pending test or requests rollback of a running test.

Home-trust admission is temporarily suspended on the candidate network without modifying the saved policy, so a different LAN is not trusted merely because the old LAN was trusted. Successful changed credentials disable stored home trust, matching USB wifi-config behavior. Existing Home/Direct browser keys and the Direct Wi-Fi password are retained; an address/origin change can still require physical pairing. Failure retains the old home-trust policy. Background autosaves of other settings during a trial still capture the old Wi-Fi credentials and saved policy, not the candidate.

Network names are 1..32 bytes without NUL/control bytes. Passwords are empty only for an explicitly open network, 8..63 bytes, or 64 hexadecimal characters. Browser UTF-8 is hex-encoded in the private POST body to preserve spaces, separators and non-ASCII text, not to encrypt it. Nothing is put in a URL, public token fingerprint or browser persistent storage. The input is cleared after a submitted attempt, and the clock never fills or publishes the saved password. Status and USB progress contain no password. The command body is cleared when consumed, mode/epoch reset clears the command cache, and the transaction password is cleared on cancellation/completion/recovery. The active saved password remains in the existing private configuration as before.

## Main-loop transaction and protocol

The pure phone_wifi controller has pending, testing, restoring, accepted/saved and terminal cancellation/failure/recovery-failure states. No radio operation, sleep or Flash write runs in an HTTP callback. At the end of the five-second grace interval the main loop rechecks source mode, epoch and idle conditions. After its own switch, expected mode/IP epoch changes do not cancel the trial. Only a newly attempted home connection can qualify: the async attempt must have been accepted and then observed ready. Cached link-up state, including after a rejected async start, cannot qualify. A ready result after the deadline rolls back. Restoration first configures old credentials, then restarts Direct. A failed Direct restart keeps temporary distrust until Direct or a new old-home join becomes ready. The last-known home address is not overwritten by an unaccepted trial.

`wifi_control:true` advertises the optional no-store `/wifi.json` response with a separate 2 KiB allocation: epoch, state/reason, request ID, remaining seconds, Direct/availability flags, saved/test SSIDs and address. It contains no credential or browser key. Failed optional metadata disables setup without hiding unrelated controls. Public SSIDs use the existing bounded JSON escaping.

`/wifi` accepts `test <1|2> <SSID hex> <password hex or ->`, `cancel 0`, `scan 0` and `forget <1|2> <profiles revision>`. The legacy `test <SSID hex> <password hex or ->` form selects Main in the existing credential/epoch/ID/nonce envelope. The legacy longest valid body is 264 bytes with a 32-byte SSID, 64-character PSK and maximum 32-bit IDs. The four existing POST contexts increase their body buffers from 128 to 288 bytes, adding 640 bytes of static storage; no extra concurrent client is added. The private command payload and transaction also hold a bounded candidate. This does not establish runtime RAM or four-client audio margins. The explicit-slot body is at most 266 bytes and still fits the existing 288-byte POST buffers. Backup credentials use conditional Flash v18 as described below; sector boundaries and Direct-key storage are unchanged.

## Two-profile connection policy

At boot/configuration the clock tries Main first, or Backup if Main is empty. Each asynchronous join has a 15-second deadline. With both profiles configured, failure selects the other profile after one second; after both attempts fail, the next cycle waits 30 seconds. A healthy Backup connection stays on Backup until it disconnects or the configuration changes; there is no signal-based roaming. Lost connections retry the current profile before falling back. With one profile, the existing 10/60-second retry policy remains.

A candidate test temporarily uses only that candidate, so a successful fallback cannot validate an incorrect password. Success replaces only the selected saved slot, restores the two-profile runtime configuration and keeps the validated association. Cancellation/failure keeps both old profiles. Changed credentials or forgetting a profile disable Home trust; remembered browser permissions and the Direct password remain. USB wifi-config updates Main and retains Backup; wifi-clear clears both.

## Search and resource boundaries

Search uses the SDK asynchronous radio scan in the current mode. It does not switch modes or save anything. The bounded catalogue holds the strongest 12 distinct visible SSIDs, sorted by signal; hidden/control-containing names and the clock's own AP are omitted. The interface shows names, coarse signal and supported/open security, without MAC addresses. Duplicate access points with the same SSID appear once. A wired second router does not itself create a second profile unless it advertises a different SSID.

The UI deadline is 15 seconds. If the driver does not complete, manual SSID entry and normal controls resume. The SDK exposes no safe abort API; another search waits until the old driver scan completes or the clock restarts. Late results after the deadline are ignored. Real discovery in Direct mode still needs verification with this SDK/radio firmware; a software PASS is not proof of AP-mode scan support.

The no-store /wifi-scan.json response has a separate 4096-byte temporary allocation; /wifi.json remains 2048 bytes and adds both SSIDs, open flags, selected/connected slot, profile revision and search availability. Neither includes passwords/BSSIDs. Catalogue capacity and response sizes are bounded, but four real concurrent browsers with audio and runtime RAM margins still require device testing.

## Flash compatibility and rollback

An occupied Backup slot selects record v18: 744 bytes, final CRC at offset 740, within the existing three 256-byte programmed pages and unchanged A/B sectors. Its v17 prefix retains all previous fields and extension rules. Records v1-v17 load with an empty Backup, without writing during load. Removing Backup returns subsequent saves to the appropriate older encoding. Corruption falls back to the other valid sector.

Older firmware cannot read a v18 record. Do not downgrade after saving Backup without a settings-preservation plan. Removing Backup and waiting for one autosave is not proof that both A/B sectors now contain an older format; verify both records or explicitly back up/reprovision settings before rollback.

## Compact connection interface candidate

Connection is one section with current mode/address and one applicable mode action: Connect directly in Home, Use home network in Direct. The current mode is information rather than a disabled action. Cancel switch appears only during a pending mode switch. Saved networks and Browser access are collapsed by default; detailed help remains optional. Editing opens only after selecting a profile in Direct. Close clears/masks its draft password without sending a command. The bounded search list uses short name/security/signal rows; choosing a result hides the list and leaves the selected name in the editor. Removal is secondary, under its own disclosure.

Starting a confirmed connection moves the viewport once to the common Connection block. The saved-profile editor, scan list and browser administration are hidden while the transition is active. During the five-second live grace period, Cancel connection is available. It disappears when the server no longer allows cancellation or the source connection is gone. The page never offers to cancel an already disconnected radio operation.

After the expected disconnection, the page clears stale ready/address text and keeps one next-step instruction. A local presentation countdown is bounded to 50 seconds for a credential trial and 65 seconds for a mode switch; it is an estimate, not evidence of radio completion. Once it expires offline, the page asks the user to reconnect and check the result rather than claiming an indefinitely running test. Live server pending/testing/restoring states take precedence when reachable. Recovery can still wait for idle audio. No browser can switch the phone's Wi-Fi or monitor an unreachable destination through this single-radio-mode design.

A previous attempt's saved/failed/cancelled result cannot dismiss a new handoff. The explicit-Connect candidate matches the operation source epoch and request ID, including when IDs restart after an address change; older metadata uses the previous changed-ID fallback. Refusal/cancellation/current destination metadata clears the appropriate handoff. Missing optional network metadata clears stale ready information without hiding unrelated controls. Existing native-picker background-render suppression, epochs, permissions, retries, radio behavior and Flash v18 policy are retained.

Software acceptance includes 26 registered tests and real Chrome fixtures at 360/412/960 pixels with enlarged text. Checks cover compact idle actions, collapsed administration, profile selection/Close, password clearing, selected-result collapse, pending cancellation, hidden inactive forms, bounded offline instructions, stale-result isolation, return after cancellation and no horizontal overflow. Device acceptance of the compact UI remains pending installation approval.

## Explicit saved-network Connect candidate

The user reported that selecting Main did not connect while Backup was active. Profile selection only opened the editor; that control was ambiguous. The candidate replaces the selector with two visible rows. Each row has its profile name, SSID and current/priority status. A non-current saved row has Connect; each row has Edit or Add. The current row says Connected and omits Connect. Edit changes credentials, Connect reuses the stored credentials. Main/Backup specify startup order, not clickable connection modes. Home networks is open by default; browser administration stays collapsed. In Direct, explicit row Connect replaces the ambiguous generic Use home network action for clients supporting the new API.

### Design references and choice

[Apple Wi-Fi settings](https://support.apple.com/en-mide/guide/mac-help/mh11935/27/mac/27) separates joining a known network from its settings and forgetting. [ESPHome captive portal](https://esphome.io/components/captive_portal/) separates provisioning/recovery from normal connection; its [Wi-Fi component](https://esphome.io/components/wifi/) also documents multiple-network selection and fallback. [Home Assistant network settings](https://www.home-assistant.io/docs/configuration/network) was considered as a centralized configuration model. For this two-profile clock, explicit row Connect/Edit was chosen over another mode selector or a full provisioning wizard: two networks remain visible, the primary action has a single meaning, and the existing single-mode radio/recovery is reused. This is a design choice, not a claim that one interface is universally best. No external UI framework, font, Internet dependency or network stack is imported.

### Connection and failure policy

From Home or Direct, Connect asks for confirmation, waits five seconds with Cancel connection available, then tests only the selected saved SSID for at most 45 seconds. No password is requested or returned. A new accepted join and IPv4-ready state are required, so fallback to another network cannot be mistaken for success. The selected network stays active while healthy. A successful saved Connect does not write settings, reorder profiles, change Home trust, change Direct credentials or revoke browser permissions. Reboot still tries Main first; normal fallback resumes after a successful connection.

On failure from Home, the clock restores both saved profiles and tries the previous runtime profile first, then its normal fallback. Recovery is a reconnection attempt, not a guarantee that an unavailable previous router can be reached. If both home networks fail, physical Phone Control/Direct remains the recovery route. On failure from Direct, the same Direct AP is restored; failed AP startup is reported separately. Active audio can defer restoration as before. The browser retains bounded handoff instructions, and the current network is reported separately from the result of the failed request. On a shared LAN, the page may recover without changing the phone's Wi-Fi; only follow reconnection steps if the page stops updating. Different IP/origin or permissions can still require the existing browser pairing process.

### Protocol and invariants

Authenticated /wifi connect <1|2> <profiles revision> uses the existing epoch/ID/nonce envelope and Home-peer/scoped-token admission. A stale revision, empty slot, already-current ready profile or competing trial/switch is rejected. Replays reuse the cached result and cannot start another attempt. Main-loop scheduling, idle checks, command invalidation and secret clearing reuse phone_wifi; pending mode/source/epoch changes cancel safely. Public current/home addresses are withheld until a fresh confirmed home connection, so a failed target's cached IP cannot become a valid recovery address. The firmware keeps a private copy of the saved credentials only for the transaction; terminal paths clear its password. No password enters URLs or public status.

Wi-Fi metadata adds connect_available, saved_connect, return_direct and request_epoch. Source epoch plus request ID identifies the operation across its own mode/address changes; ID reuse in a later session cannot be mistaken for old completion. The first both advertises support and reports idle admission. Old metadata leaves explicit Connect unavailable and retains the previous generic Home action. No root status allocation or Flash format/sector changes are introduced. Browser controls also wait for queued scalar edits; confirmation warns about unapplied browser drafts.

# Pi2Clock G2 - новая microSD, автономность и сетевые данные

**Статус:** спецификация каталогов для **новой** карты. Не имеет совместимости с папками 01..19 для DFPlayer/G1. В ZIP в комплекте содержится **только каркас каталогов и JSON-примеры, без звука и без музыки**. Нельзя копировать её на действующую карту G1 без резервной копии.

## 1. Формат и ограничения

- FAT32, одна доступная разделу файловая система, именование латиницей `snake_case`, короткие уникальные `track_id`; содержимое `artist/title` UTF-8 в JSON. Рекомендовано сначала тестировать microSD 8/16/32 GB класса A1/U1 от надёжного производителя, ёмкость и совместимость проверить.
- Текущий G1 драйвер `firmware/pico2w_c/drivers/sd_fat32.c` был ограничен именами 8.3 и вложенностью; **обязательная доработка G2**: FatFs с LFN (или проверенный эквивалент), папки нескольких уровней, безопасная запись, запрет чтения/записи во время несогласованных SPI транзакций с OLED.
- Один `/PI2CLOCK/` в корне карты, имена папок и файлов на латинице. Файлы `.mp3/.wav` идентифицируются по **пути и манифесту**, не по номеру DFPlayer.
- Схема файловой системы version `g2-sd-1`; изменять только с миграцией. При первой загрузке проверять целостность, не удалять неизвестные файлы пользователя.

## 2. Дерево папок

```text
microSD (FAT32)
└── PI2CLOCK/
    ├── manifest.json                  # версия SD и список РЕАЛЬНО установленных пакетов
    ├── config/
    │   ├── README.md                  # какие настройки можно импортировать/экспортировать
    │   └── user_settings.example.json # пример, НЕ активный файл прошивки
    ├── voices/
    │   ├── README.md
    │   ├── ru-RU/
    │   │   ├── female_01/{voice.json,phrases/,tokens/,templates/}
    │   │   ├── female_02/{...}
    │   │   ├── female_03/{...}
    │   │   ├── male_01/{...}
    │   │   ├── male_02/{...}
    │   │   └── male_03/{...}
    │   └── de-DE/ (аналогично 6 голосов)
    ├── music/
    │   ├── catalog.json              # треки и коллекции (изначально пусто)
    │   ├── collections/
    │   │   ├── classical/             # сюда добавить свои лицензированные mp3
    │   │   ├── disco/
    │   │   └── ru_music/
    │   └── playlists/                 # отдельные плейлисты, позже
    ├── sounds/
    │   ├── ui/                        # click, confirm, error WAV (пока пусто)
    │   ├── alerts/                    # timer_done, alarm, battery_low WAV
    │   └── chimes/                    # hourly, half_hour WAV
    ├── cache/
    │   ├── weather/                   # только НЕОБЯЗАТЕЛЬНЫЕ сохранённые прогнозы
    │   └── ntp/                       # необязательная последняя успешная синхронизация
    ├── logs/                           # кольцевой диагностический лог; лимиты размера
    ├── recordings/                     # опц. голосовые заметки от INMP441
    ├── updates/                        # только служебная загрузка, прошивка защищает A/B
    └── backup/                         # экспорт настроек/списка будильников, не секретов
```

**Ограничение ZIP:** пустые каталоги могут не отображаться после копирования на Windows, поэтому в них лежат служебные `.gitkeep` (не аудиофайлы). Директории голосов в каркасе не означают наличие записей.

## 3. Формат музыкального каталога

- `music/catalog.json` - массив записей `{track_id, path, artist, title, collection, enabled}`; `track_id` не зависит от нумерации/сортировки FAT32. Плейлисты хранят **track_id**, а не индексы музыкальных файлов.
- Пример после добавления реальной музыки:

```json
{
  "schema": "g2-music-1",
  "tracks": [
    {
      "track_id": "song_0001",
      "path": "music/collections/classical/artist_-_title.mp3",
      "artist": "Example Artist",
      "title": "Example Title",
      "collection": "classical",
      "enabled": true
    }
  ]
}
```

- При удалении/переименовании файла старый `track_id` становится недоступен; проигрыватель пропускает трек, будильник переключается на безопасный системный сигнал, а событие пишется в лог. Нельзя считать конкретное число файлов в папке равным числу песен.
- Режимы: последовательный, shuffle, repeat-one, all_music; в случайную подборку не включать `voices/` и `sounds/`.

## 4. Голосовые пакеты

- Один пакет = один язык + один голос: `voices/ru-RU/female_01/`, `voices/de-DE/male_02/` и т.п.
- `voice.json`: ID, язык, человекочитаемое имя, лицензия, параметры звука, состояние `installed=false`, список поддержанных фраз. Не считать пакет доступным, пока нет самих WAV/MP3 и успешной валидации.
- `phrases/` для **полных неизменяемых** фраз, например `system.ready.wav`, `wifi.connected.wav`. `tokens/` - отдельные числа, даты, единицы, порядковые. `templates/` - грамматические сценарии сборки; нельзя сохранять переменные `[TIME]` как полноценный WAV.
- Имена примеров (после генерации):

```text
voices/ru-RU/female_01/phrases/system.ready.wav
voices/ru-RU/female_01/phrases/sound.enabled.wav
voices/ru-RU/female_01/tokens/timer/first.wav
voices/ru-RU/female_01/tokens/numbers/14.wav
voices/ru-RU/female_01/tokens/units/minutes_acc_many.wav
voices/de-DE/female_01/phrases/system.ready.wav
voices/de-DE/female_01/tokens/timer/one.wav
voices/de-DE/female_01/tokens/units/minuten_plural.wav
```

Шаблон `timer.finished` RU: `timer_first + timer_on + number_14 + minutes_acc_many + timer_finished`, результат «Первый таймер на четырнадцать минут завершён». Шаблон DE независимо составляется с немецким порядком слов; не переводить русский шаблон токен за токен.

## 5. Что нужно на карте в автономном режиме

**Обязательно для полного офлайн-воспроизведения:** языковые WAV/MP3 (хотя бы RU+DE по одному голосу), их манифесты, `sounds/alerts/` и `sounds/chimes/`, музыка по желанию и её каталог. Собственно часы и таймеры должны работать и без SD, но тогда голос/музыка отсутствуют; минимальный звуковой beep из встроенной flash/PIO и OLED/WS2812 обязателен для критических уведомлений (разработать).

**Надёжно хранить во Flash, а не только на SD:** основное время/RTC-состояние, часовой пояс/DST, график будильников, таймеры и идентификаторы событий, язык и выбор голоса, уровень громкости (отдельно local/BT), сохранённые Bluetooth устройства, Wi-Fi credentials, разрешения web UI, OTA A/B метаданные. При наличии SD допускается резервная копия **без паролей и ключей**. При отсутствии сети время берётся из DS3231 (если установлен) или сохраняется внутренним таймером только пока питается устройство; NTP не нужен для музыки, голосовых фраз и таймеров.

**Предупреждение по таймерам после сброса:** сохранение длительности/времени окончания и корректное восстановление зависит от достоверных часов и записанного состояния; нельзя обещать сохранение хода таймера при полной потере питания без RTC и специального журнала.

## 6. Что нужно при подключении к сети

- Wi-Fi и BT - аппаратные радиомодули Pico 2 W, файлы драйверов находятся в прошивке, не на SD.
- NTP синхронизирует часы, время DST/Europe/Berlin вычислять по проверенным правилам прошивки. DS3231 при наличии получает поправку; при отсутствии NTP использовать RTC/ручную установку с индикатором достоверности.
- `cache/weather/` хранит только последние данные прогноза с timestamp/expiry; **просроченный кэш нельзя выдавать за текущую погоду**. Никакой обязательной зависимости от сервера для будильников.
- Web UI, права доступа, OTA A/B: **из G1**, должны хранить критичные настройки в энергонезависимой Flash; SD используется опционально для временных файлов, журналов или экспортов. Запись OTA не должна конфликтовать с аудио/дисплеем и не должна стирать действующий слот без верификации.
- Bluetooth A2DP из G1 переносится с сохранёнными адресами/названиями, но G2 должен проверить совместную работу I2S, MP3, SD, OLED и CYW43. Встроенный динамик - моно смесь L+R (проверить SD/MODE либо выполнить программное усреднение); Bluetooth - полное стерео.

## 7. Аудио форматы и ресурсы

- Для речевых **коротких** токенов предпочтительно PCM WAV mono 16 bit 16/24 kHz (нет MP3 encoder delay и заметных стыков). Длинные сообщения и музыку можно хранить MP3; подтвердить адаптацию частот дискретизации к I2S, обмену BT и доступной RAM.
- OLED 256×64×4bit = 8192 байта кадрового буфера; к аудио-буферу предъявлять нагрузочный тест. Не держать весь MP3 в RAM; читать чанками через FAT32. Совместную SPI1 между SD и OLED сериализовать (CS раздельные).
- В начале выпуска можно применять упрощённые имена файлов **8.3**, но это НЕ эквивалент запрошенной удобной иерархии каталогов; настоящий план требует VFAT LFN и глубокого обхода. Для выпуска G2 валидатор `manifest.json` обязателен.

## 9. Нерешённые вопросы для реализации

- Техническая лицензия и полный авторский набор WAV всех 12 голосов.
- Потребление OLED и карточки; утверждение 3.3 В регулятора и схемы Power Path.
- Статус GPIO при одновременном RX микрофона и TX усилителя.
- FAT32 LFN, длинные имена, рекурсивный поиск, права на запись, износ карты.
- Распознавание отключённой/плохой SD и graceful fallback без пропуска таймера.

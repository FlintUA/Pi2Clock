# PicoClock V4 - концепция пользовательского интерфейса и управления

**Статус:** предварительная согласованная концепция для проверки на аппаратном прототипе  
**Дата:** 13.11.2026  
**Назначение:** автономные говорящие настольные часы для кухни, спальни, прихожей и рабочего стола.

## 1. Основное решение

Вместо двух механических энкодеров **TIMER** и **VOLUME** использовать **один центральный поворотный энкодер с кнопкой**, являющийся универсальным элементом навигации и изменения параметров.

- **Вращение вне редактора** - выбор функции или пункта меню.
- **Короткое нажатие** - вход в выбранный пункт или подтверждение значения.
- **Вращение в редакторе** - изменение выбранного параметра.
- **Повторное короткое нажатие** - подтверждение и сохранение (для простых параметров); в многошаговых редакторах - переход к следующему полю.
- **Длинное нажатие** - возврат на главный экран, с безопасным выходом из редактирования.
- **Пять сенсорных кнопок TTP223** - быстрый вызов важных функций, без необходимости проходить через меню.

**Задача:** упростить лицевую панель 3D-печатного корпуса, сохранив доступ ко всем функциям. Сенсорные кнопки выбраны прежде всего ради бесшумности.

## 2. Аппаратная компоновка управления

| Элемент | Количество | Назначение |
|---|---:|---|
| Энкодер с нажатием | 1 | Навигация, регулировка, выбор и подтверждение |
| TTP223 | 5 | Бесшумные кнопки быстрого доступа |
| WS2812 | 4 | Подтверждение касания, тихие уведомления, статусы |
| OLED SSD1322 | 1 | Основная графическая обратная связь |

**Дисплей для прототипа:** заказаны 2 OLED 3,12 дюйма, 256×64, SSD1322. Более крупный SSD1322 (5,5 дюйма) можно рассмотреть позднее; при совместимых режимах и командах драйвер и логика интерфейса должны быть максимально переиспользуемыми.

**Примечание:** окончательное соответствие пяти TTP223 существующим пяти физическим кнопкам PicoClock V3 необходимо сверить с исходной схемой/прошивкой, прежде чем менять распиновку. Нельзя считать предложенные ниже назначения уже реализованными.

## 3. Иерархия интерфейса

```text
HOME (основной экран)
  |
  +-- поворот энкодера --> SELECT_FUNCTION (выбор функции)
  |                       |
  |                       +-- Volume --> EDIT_VOLUME --> подтвердить
  |                       +-- Timers --> TIMERS_OVERVIEW --> TIMER_DETAIL / EDIT
  |                       +-- Alarms --> ALARMS_OVERVIEW --> ALARM_EDITOR
  |                       +-- Music --> MUSIC_PLAYER
  |                       +-- Weather --> WEATHER_VIEW
  |                       +-- Bluetooth --> BT_MENU
  |                       +-- Settings --> SETTINGS_MENU
  |
  +-- TTP223 --> быстрые действия / немедленный переход к функции
  |
  +-- завершение таймера / будильник --> PRIORITY_NOTIFICATION
```

### Главное правило

Энкодер выполняет **контекстное действие**, но текущий контекст всегда явно обозначается на OLED. Из любой вложенной страницы пользователь должен иметь понятный путь назад; ключевые события доступны без навигации.

### Базовый цикл управления

1. На HOME поворотом открыть выбор функций.
2. Вращением выделить нужный пункт (например, «Громкость»).
3. Нажать энкодер - открыть регулировку.
4. Вращением изменить параметр.
5. Нажать энкодер повторно - подтвердить значение.
6. Вернуться на HOME либо к предыдущему уровню (точное поведение уточнить испытаниями).

Для настроек, состоящих из нескольких полей (часы/минуты будильника, параметры таймера и т. д.), короткое нажатие означает **подтверждение текущего поля и переход дальше**, а окончательное сохранение выполняется на последнем шаге.

## 4. Главный экран HOME

**Обязательные приоритеты:**

- Крупное текущее время.
- Дата/день недели.
- Небольшие статусы Wi-Fi и Bluetooth.
- Ближайший будильник.
- Активный таймер или краткое сообщение о количестве таймеров.
- Погодная информация, когда имеется актуальный прогноз.

Для OLED **256×64** надо закладывать ограничения: не все параметры должны постоянно присутствовать в развёрнутом виде. Основной экран показывает наиболее важное, дополнительные сведения доступны через переключение экранов.

В спящем/обычном режиме OLED работает на сниженной яркости; при управлении временно повышает яркость. Ночной режим и тихий режим независимы.

## 5. Регулирование громкости

**Пример:** HOME -> вращение: «Громкость» -> нажатие -> изменение вращением -> нажатие: подтвердить.

Требования:

- Регулировка применяется сразу во время вращения; дополнительное нажатие только завершает режим.
- На OLED отображается шкала и числовое значение.
- Сохраняются **независимые уровни громкости встроенного аудиотракта и Bluetooth**, уже заложенные в существующем проекте.
- Кнопка BACK/отмена или длинное нажатие дают предсказуемый выход.
- Тайм-аут бездействия возможен для простых режимов (предварительный ориентир 5 секунд, уточнить тестированием).

**Важно:** при активном воспроизведении быстрый доступ к регулировке громкости через одну из TTP223 желательно сохранить, чтобы не приходилось прокручивать меню.

## 6. Три независимых таймера

В PicoClock V3 сейчас один таймер; для V4 запланированы **три одновременно работающих**.

### Экран TIMERS_OVERVIEW

- Если активных таймеров 2 или 3, показывать **все одновременно**.
- Таймер с наименьшим оставшимся временем - крупно.
- Остальные - компактно, но читаемо.
- Завершённый, но не подтверждённый таймер имеет высший приоритет.
- Неактивные можно показывать сокращённо либо скрывать, в зависимости от свободного места.

Условная компоновка для широкого 256×64:

```text
ТАЙМЕРЫ       3 АКТИВНЫ
T1
04:32      T2  12:45
           T3  28:16
```

### Управление таймерами

- Вращение в списке - выбор T1/T2/T3.
- Нажатие - открытие выбранного таймера.
- В редакторе вращение меняет длительность только **остановленного** таймера.
- Запуск, пауза, остановка, сброс - отдельные явные команды.
- **Поворот энкодера не должен случайно менять длительность работающего таймера.**
- Если одновременно завершатся несколько таймеров, сообщения воспроизводятся последовательно.

### Голосовые сообщения (согласованное требование)

**«Первый таймер на 14 минут завершён».**

Нужно объявлять **номер таймера и исходную длительность**, а не оставшееся время. Для этого хранить `initial_duration` отдельно от `remaining_duration`. Предусмотреть грамматически корректные формы («одна минута», «две минуты», «пять минут»), очередь и повторные уведомления до подтверждения.

## 7. Сенсорные кнопки TTP223 - быстрые действия

Пять TTP223 не заменяют логику энкодера: они обеспечивают **однокасательный доступ к важным действиям**.

**Предварительный вариант распределения (не утверждён):**

| Сенсор | Возможное быстрое действие |
|---|---|
| 1 | Таймеры / переход к экрану таймеров |
| 2 | Громкость / MUTE |
| 3 | Будильники / подтверждение при срабатывании |
| 4 | Настройки / выбор режима |
| 5 | BACK / отмена / возврат на HOME |

Приоритет - максимально сохранить привычную семантику существующих пяти кнопок. Старые комбинации, в частности длительное ALARM для музыкального проигрывателя, должны быть инвентаризированы до изменения прошивки.

**Обязательные испытания TTP223:**

- Срабатывание через PLA/PETG и выбранную толщину передней панели (например, сначала 1-2 мм).
- Короткие/длинные касания и отсутствие ложных повторов.
- Поведение при влажных пальцах и помехах от питания, аудио и WS2812.
- Отключаемое световое подтверждение касания.

## 8. Приоритетные уведомления и тихий режим

Четыре WS2812 предназначены не только для декора, но и для **визуального канала уведомлений**.

| Событие | Предлагаемое поведение |
|---|---|
| Подтверждение касания | Краткая мягкая вспышка, отключаемая |
| Тихий режим включён | Краткое синее подтверждение |
| Таймер завершён | Оранжевая пульсация до подтверждения |
| Будильник сработал | Красная пульсация в бесшумном режиме |
| Подключение Bluetooth | Краткий зелёный сигнал |
| Обычная работа | Светодиоды выключены или почти незаметны |

Цвета предварительные и в перспективе настраиваемые.

**Тихий режим:** отключает голосовые/звуковые уведомления, но не события; информация остаётся на OLED и WS2812.  
**Ночной режим:** снижает яркость OLED/WS2812 (или отключает их по расписанию); может работать независимо от тихого.

При срабатывании будильника/таймера интерфейс показывает **приоритетное уведомление**, которое можно подтвердить без поиска соответствующей функции в меню. Способ подтверждения должен исключать случайный сброс других таймеров.

## 9. Правила обработки событий и UX

1. **Стандартизировать события ввода:** `ROTATE(+/-)`, `PRESS`, `LONG_PRESS`, `TOUCH_i`, `TOUCH_i_LONG`.
2. **Контекстный Input Manager:** диспетчер переводит события в действия текущего экрана.
3. **Явное выделение:** выбранная функция и редактируемое поле всегда визуально различимы.
4. **Защита от случайного изменения:** работающие таймеры, будильники и другие критичные параметры не изменять без входа в редактор.
5. **Отмена:** в многошаговых меню не применять неподтверждённые изменения автоматически.
6. **Приоритет событий:** завершение таймера и будильник показывать поверх меню, сохраняя возможность продолжить ранее прерванную настройку.
7. **Стабильность CORE:** Wi-Fi, погодные запросы и Bluetooth не должны задерживать локальные таймеры и будильники.
8. **Доступность:** критичные операции должны оставаться понятными без голоса и при выключенной подсветке WS2812.

## 10. Что проверить на макете

После получения двух OLED 3,12 дюйма и монтажной платы собрать настольный прототип с одним энкодером и TTP223. Проверить:

1. Удобство одного энкодера для ежедневного управления, особенно громкостью при проигрывании музыки.
2. Читаемость экрана 256×64 с расстояния и компоновку трёх таймеров.
3. Достаточность пяти быстрых сенсорных кнопок.
4. Работу длинных касаний и случайные срабатывания.
5. Поведение меню при одновременных уведомлениях.
6. Яркость OLED днём, в простое и ночью.
7. Видимость и комфорт яркости четырёх WS2812 в тихом режиме.
8. Возможность единого драйвера и UI при будущем переходе на OLED 5,5 дюйма SSD1322.

## 11. Статус решений

| Решение | Статус |
|---|---|
| Один центральный энкодер с нажатием вместо двух | **Выбран для испытаний V4** |
| Вращение - выбор/изменение; нажатие - вход/подтверждение | **Основная концепция** |
| Пять TTP223 вместо пяти физических кнопок | **Предпочтительный вариант** |
| Четыре WS2812 для тихих уведомлений | **В плане V4** |
| Три таймера с одновременным отображением | **В плане V4** |
| Крупный ближайший таймер, остальные компактно | **В плане V4** |
| OLED SSD1322 3,12 дюйма, 256×64 | **Два модуля заказаны** |
| MAX98357A | **Модуль уже есть в наличии** |
| Окончательная карта сенсорных кнопок | **Открыто - сверить V3** |
| Тайм-ауты, короткие/длинные нажатия, сценарии BACK | **Уточнить на прототипе** |
| Форма и габариты корпуса | **После аппаратной примерки** |

## 12. Основная рекомендация

Реализовать навигацию как **конечный автомат UI** с независимым слоем ввода и графической абстракцией дисплея. Тогда аппаратное исполнение (один или два энкодера; механические или сенсорные кнопки; OLED 3,12 или 5,5 дюйма) можно будет менять без переписывания логики будильников, таймеров, звука и сети.

**Следующий практический шаг:** собрать и оценить макет после получения дисплеев и монтажной платы. До этого не фиксировать геометрию корпуса и окончательные назначения сенсорных кнопок.

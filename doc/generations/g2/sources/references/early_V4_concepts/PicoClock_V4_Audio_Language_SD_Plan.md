# PicoClock V4 - архитектура аудио, локальные фразы и новая структура microSD

**Статус:** проектное ТЗ / аудит по состоянию на 14.11.2026. **Не реализовано.**  
**Репозиторий:** https://github.com/FlintUA/Speaking-Timer-Clock-Raspberry-Pi-Pico  
**Источники:** `main` (снимок дерева `sound/_sdcard`, `source/v3/main.py`, `source/v3/audio.py`, `firmware/pico2w_c/drivers/sd_fat32.c`, `firmware/pico2w_c/audio/speech.c`), `develop/v3` (`doc/CONTROLS_AND_MODES.md`, `firmware/pico2w_c/audio/speech.c`, `app/countdown.c`), проектные обсуждения. В README рабочая MicroPython-ветка обозначена v3.10.0; экспериментальная C-ветка не считается готовой заменой.

> **Разделение достоверности:** **[ФАКТ]** проверено в указанном файле репозитория/прошлой беседе; **[ПЛАН]** предлагаемое для V4; **[ПРОВЕРИТЬ]** нельзя гарантировать без реальной SD и прослушивания файлов. Значения из `sound/_sdcard` описывают **версию в Git**, а не обязательно актуальную физическую microSD в часах.

## 2. Языки и голоса

**Обязательный старт V4:** `ru-RU`, `de-DE` - интерфейс и речь. Для каждого языка шесть голосов `female_01`, `female_02`, `female_03`, `male_01`, `male_02`, `male_03`. Таким образом, при полном покрытии RU+DE **12 отдельных голосо-языковых пакетов**, не шесть смешанных RU/DE пакетов. Если память/объём записи ограничены, допускается выпустить сначала 1 качественный голос на каждый язык, а остальные догрузить без изменения API. Это **поэтапная рекомендация**, не отмена цели шести голосов.

**Перспектива:** `uk-UA`, `en-US` - **предложение**, не подтверждённое поддержкой текущей прошивки и аудиофайлов. Не помечать как готовые; для них отдельно разработать числительные, даты и грамматику.

Параметры пользователя: `ui_language`, `speech_language`, `voice_id`, `announce_volume_local`, `announce_volume_bluetooth`. Разрешить язык GUI и язык речи выбирать отдельно, если соответствующий полный пакет установлен. Отсутствующий пакет не должен приводить к автоматическому переходу на другой язык без явного уведомления.

## 3. Проект размещения файлов на microSD (V4)

**Имена:** английские латинские `snake_case`, семантические, без обязательных цифровых префиксов, UTF-8 только в метаданных/отображаемых названиях. Путь на FAT лучше хранить в латинице для совместимости. **Не использовать номер файла как его идентичность.** Регистр имен согласовать (нижний).

```text
/PICOCLOCK/
  manifest.json                      # версия разметки, языки, голоса, checksums
  config/
    audio_profiles.json              # конфигурация профилей, при переносе с flash
  voices/
    ru-RU/
      female_01/
        voice.json                    # голос, лицензия, полнота, sample rate
        phrases/                      # целые короткие сообщения
          timer_set.wav
          timer_started.wav
          timer_paused.wav
          timer_resumed.wav
          timer_cancelled.wav
          timer_finished.wav
          alarm_activated.wav
          alarm_dismissed.wav
          sound_enabled.wav
          sound_disabled.wav
          bluetooth_connected.wav
          wifi_disconnected.wav
        tokens/
          timer/                      # timer_first.wav, timer_second.wav, ...
          numbers/                    # 0..99 и разряды, формы при необходимости
          units/                      # minute_one.wav/minute_few.wav/minute_many.wav
          clock/                      # hours/minutes с нужной грамматикой
          calendar/                   # weekdays, months, ordinal days, years
          weather/                    # cloudy, rain, snow, feels_like, etc.
        templates/                    # необязательно: полные частые объявления
          timer_finished_14m_t1.wav
      female_02/ ...
      female_03/ ...
      male_01/ ...
      male_02/ ...
      male_03/ ...
    de-DE/
      female_01/ ...
      female_02/ ...
      female_03/ ...
      male_01/ ...
      male_02/ ...
      male_03/ ...
  sounds/
    startup.wav
    ui_touch.wav
    ui_confirm.wav
    ui_error.wav
    timer_short.wav
    timer_long.wav
    timer_repeat.wav
    alarm_signal.wav
    half_hour_double_beep.wav
    clock_chime_intro.wav
    clock_chime_01.wav ... clock_chime_12.wav
  music/
    playlist.json
    artist_name - track_title.mp3
    ...
  cache/
    weather.json                     # опциональный кэш, атомарная запись
  legacy_v3_backup/                 # НЕ для продуктивного V4, миграционный архив
    01/ 02/ ... 19/
```

**Важная доработка:** стандартное дерево будет работать только после добавления **LFN и вложенных путей** в файловый слой C-проекта. При невозможности использовать LFN на первом стенде можно временно использовать `8.3`-алиасы и отдельный JSON-манифест, но считать их временной совместимостью, а не целевой схемой. Настоящие `timer_finished.wav` и длинные имена треков требуют LFN; короткие `alarm.wav` тоже могут работать, но каталог `voices/ru-RU/female_01` требует рекурсивного обхода.

### Пример `manifest.json` (проект)

```json
{
  "schema_version": 1,
  "audio_root": "/PICOCLOCK",
  "languages": ["ru-RU", "de-DE"],
  "required_voices_per_language": ["female_01", "female_02", "female_03", "male_01", "male_02", "male_03"],
  "default_language": "ru-RU",
  "default_voice": "female_01",
  "audio_format": {"voice": "wav_pcm_s16le_mono_22050", "music": "mp3"},
  "music_index": "music/playlist.json"
}
```

Для первых тестов голосовые токены рекомендуется унифицировать как WAV PCM mono 16-bit / 22050 Hz или 24000 Hz (точную частоту согласовать с I2S/Bluetooth трактом). Это **проектный формат**, который надо проверить по CPU, скорости SD и объёму. Музыка остаётся MP3; экспериментальный Helix в C уже поддерживает ограниченный набор исходных частот 44,1/48 кГц, но единый рабочий аудиодвижок для MAX и BT ещё предстоит реализовать.

### Имена музыкальных файлов

Физическое имя: `artist_name - track_title.mp3` (UTF-8 названия допускаются только после проверки LFN/Unicode; для надёжности - латиница). `playlist.json` содержит неизменяемый `track_id`, относительный `path`, человекочитаемые `artist`, `title`, `duration_ms` (по результатам сканирования), `enabled`, `tags`.

Не связывать будильник с числом «трек 12»: связывать с `track_id`, чтобы переименование/изменение порядка файлов не изменяло мелодию будильника. Shuffle-bag, normal и repeat-one сохранить. При удалении выбранного трека - понятный fallback на стандартный сигнал, с событием в журнале/экране.

## 4. Полный каталог смысловых сообщений V4 - RU / DE

Столбец `ID` - **стабильный внутренний ключ**. Текст справа - *проектные рекомендуемые реплики*, а не транскрипция исторических MP3. Плейбек собирает реплику целиком или из токенов. `[N]`, `[DURATION]`, `[TIME]` и т.д. не проговариваются буквально.

|---|---|---|---|

### 4.2. Три таймера - обязательные сообщения

| ID | Русский | Немецкий | Пример/условие |
|---|---|---|---|
| `timer.setup` | «Настройка [ORD] таймера». | „[N]. Timer einstellen.“ | Открытие редактора, по настройке. |
| `timer.started` | «[ORD] таймер установлен на [DURATION]». | „Timer [N] auf [DURATION] eingestellt und gestartet.“ | После успешного запуска. |
| `timer.paused` | «[ORD] таймер приостановлен». | „Timer [N] pausiert.“ | |
| `timer.resumed` | «[ORD] таймер продолжен». | „Timer [N] fortgesetzt.“ | |
| `timer.cancelled` | «[ORD] таймер отменён». | „Timer [N] abgebrochen.“ | |
| `timer.finished` | **«[ORD] таймер на [DURATION] завершён».** | **„Timer [N] über [DURATION] ist abgelaufen.“** | **Точное требование пользователя для RU**. DE формулировку утвердить на прослушивании. |
| `timer.remaining` | «[ORD] таймер - осталось [DURATION]». | „Timer [N]: noch [DURATION].“ | Только по запросу. |
| `timer.acknowledged` | «[ORD] таймер подтверждён». | „Timer [N] bestätigt.“ | Обычно лучше только короткий тон/индикация. |
| `timer.all_finished` | «Все таймеры завершены». | „Alle Timer sind abgelaufen.“ | Опционально; не вместо отдельных сообщений. |
| `timer.time_invalid` | «Неверная продолжительность таймера». | „Ungültige Timerdauer.“ | UI в приоритете. |
| `timer.overlap` | «Завершились несколько таймеров». | „Mehrere Timer sind abgelaufen.“ | При одновременном событии, затем индивидуальные фразы. |

**Критично:** хранить `timer_id`, `initial_duration_seconds`, `remaining_seconds`, `state`, `ack_pending`, `sequence`. Фраза завершения использует `initial_duration_seconds`, а не нулевой остаток. При нескольких событиях - очередность уведомлений, без наложения и с исключением повторения уже подтверждённых сообщений. При тихом режиме OLED + 4 WS2812 остаются обязательными, политика аудио для alarm/timer выбирается пользователем и не должна неявно ломать исторически важное пробуждение.

**Примеры грамматики:** «Первый таймер на **1 минуту** завершён», «Второй таймер на **2 минуты** завершён», «Третий таймер на **5 минут** завершён», «Первый таймер на **1 час 2 минуты 3 секунды** завершён». В фразе запуска/завершения предлог `на` требует **винительного** («одну минуту», а не «одна минута»). Предлагается нормализованная альтернатива для TTS «Первый таймер, установленный на 1 минуту, завершён» - если слияние звучит естественнее; утверждённый пользовательский шаблон для 14 минут сохранить.

**DE примеры:** „Timer eins über vierzehn Minuten ist abgelaufen.“; „Timer zwei auf fünfundzwanzig Minuten eingestellt und gestartet.“; „Timer drei: noch eine Minute und drei Sekunden.“ Для интерфейса можно предпочесть „Der erste Timer mit einer Laufzeit von vierzehn Minuten ist abgelaufen.“ - стилистика финализируется при записи. В немецком **`eine Minute`, `eine Sekunde`, `eine Stunde`**, а с количеством больше 1 - `Minuten`, `Sekunden`, `Stunden`.

## 5. Словари и правила составления речи

- **Не собирать русские тексты из несогласованных отдельных слов.** Для `на 1 минуту` нужны винительный + склонение; для даты нужны порядковые формы; для отрицательных температур нужно `минус`; для + градусов при желании - `плюс`.
- **Оптимальная гибридная стратегия:** (a) частые короткие фразы целиком, (b) устойчивые фрагменты-переходы, (c) грамматически маркированные числа и единицы. Например `timer_first.wav` + `timer_on.wav` + `number_14.wav` + `minutes_acc_many.wav` + `timer_finished.wav`; но итог проверить на слух.
- **Для немецкого** `vierzehn Minuten`, `eine Minute`, `eine Stunde`; дата требует порядковых `ersten`, `zweiten` и предлогов, время - немецкого порядка слов.
- **Произносить секунды** в точных таймерах, если они были установлены; иначе не добавлять лишнее «ноль секунд».
- **Числа:** для времени 0-59; для таймеров до 4 часов - 0-59 секунд/минут, 1-4 часа; для погоды - диапазон как минимум от -40 до +60 (требует составных отрицательных чисел); для процентов - 0-100; для года - 2000-2099.
- **Паузы/стыки:** все фрагменты одного голоса нормализовать до одинакового уровня громкости, не делать MP3 encoder-delay между словами; минимальные паузы учитывать в шаблонах. На записи проверить 1, 2, 5, 11, 12, 14, 21, 22, 25, 101 (для больших чисел).
- **Порядок сообщения:** критичный сигнал таймера/будильника -> речь -> повторение по политике. По умолчанию не прерывать таймерное сообщение музыкой. Понижение фоновой музыки или пауза с последующим возвратом.

## 6. Миграция с DFPlayer на MAX98357A и именованные файлы

1. **Не менять рабочую V3**; создать отдельную ветку/путь с тестовой SD V4. Сделать резервную копию реальной карты и контрольные суммы.
2. Снять фактический список файлов с карты, включая размеры, даты и SHA-256; сравнить с `sound/_sdcard` и отдельно зафиксировать, каких файлов нет в Git.
3. Прослушать и составить табличное соответствие для всех старых `07`, `17`, `01/02`, `11/12`, `03/04`, `13/14`, `09`; неизвестные обозначить `unverified`, **не выдумывать перевод на основании номера**.
4. В C заменить/доработать FAT32: предпочтительно FatFs с поддержкой LFN (проверить лицензию, конфигурацию памяти и Unicode), чтением вложенных папок, UTF-8/ASCII, обработкой отсутствующих файлов и безопасной записью манифеста.
5. Ввести API `audio_play(path)`, `speech_say(event_id, params)`, `music_play(track_id)`; индекс на основании реального каталога/манифеста, а не номера DFPlayer. Разделить события, очередь, рендеринг шаблонов, декодер, PCM-микшер и вывод.
6. Согласовать формат PCM и аудиобуферы, измерить работу MP3 декодирования с SD, MAX98357A I2S(PIO), Bluetooth A2DP и экрана одновременно. Тест нагрузок, underruns и задержек таймеров.
7. Генерировать/записывать нужные RU и DE клипы для каждой из шести голосовых персон, указывать происхождение голосов и лицензию; не применять чужие аудиозаписи без права распространения.
8. Добавить валидатор: проверка schema, voice.json, наличие каждого event и токена, частоты дискретизации, длины/нулевых файлов, конфликтов имён, отсутствующего `track_id`, checksum.
9. Тест «выдернули SD» и «нет фразы»: **никакой произвольной соседней дорожки**, вместо этого экран+WS2812 и резервный beep из flash, с записью диагностического события.
10. Сохранить раздельную громкость `local`/`bluetooth`; silent/night/profile policy не должны ухудшать надёжность будильников и таймеров без явного выбора пользователя.

### Предлагаемая схема внутренних интерфейсов

```text
Timer/Alarm/Clock/Weather/Settings (семантические события)
                  |
           Speech planner
      (язык + голос + грамматика)
                  |
       Asset resolver / manifest
                  |
     Audio queue / priority / ducking
                  |
     Filesystem + decoder -> PCM ring
                  |
       +----------+----------+
       |                     |
    PIO I2S                 BT A2DP
   MAX98357A             внешняя колонка
```

`audio_play(path)` должен поддерживать настоящие имена, каталог музыки - сортировку по метаданным и стабильные `track_id`. Манифест не должен требовать полного сканирования SD при каждом срабатывании таймера: кэшировать индекс путей в RAM либо открывать по известным шаблонам; операции SD не должны блокировать системный таймер.

## 7. Приёмочные тесты

- RU/DE каждый из 5 будильников: номер **и текущее время**; отсутствие нужного файла не запускает чужую фразу.
- RU/DE три таймера: запустить `T1=14m`, `T2=1m`, `T3=1h 2m 3s`, проверить полные реплики, включая `«Первый таймер на 14 минут завершён»`.
- Несколько таймеров завершаются в одну секунду: нет потери событий, приоритет и очередь последовательны, OLED отображает все события.
- Тихий режим: пользовательская политика на звук, обязательный OLED + WS2812, подтверждение/повтор только непогашенных событий.
- Дата: 1, 2, 5, 21, 31; 2027, 2030, 2099; 00:00, 01:01, 02:02, 05:05, 23:59 на RU/DE.
- Погода: минусовая/нулевая/положительная температура, осадки, отсутствие API, просроченный кэш.
- Музыка: файл с длинным именем, пробелами и дефисом, 46-й/55-й трек, shuffle без повторов, удалённый файл из избранного будильника.
- MP3 и WAV: проверить хрипы/паузы при склейке, переключение локального MAX / BT, высокую нагрузку SPI microSD и OLED.
- На каждый голос каждого языка запускать автоматизированный `validate_voice_pack.py`: полный набор и верифицированная грамматика для типовых форм.

## 8. Решения, требующие окончательного подтверждения

1. **Реальная физическая microSD** может содержать больше дорожек, чем Git - нужна её копия или инвентаризация; данных пока не найдено для транскрипции каждого MP3.
2. **Шесть голосов:** требуется уточнить доступность, права и акустическое качество исходных синтезаторов/дикторов; сами записи ещё не созданы.
3. **Финальная немецкая фраза завершения:** предложена, но её естественность лучше согласовать с носителем языка или при прослушивании.
4. **Файловая система:** нужен рабочий LFN/вложенные каталоги, сейчас C-драйвер этого не умеет.
5. **Формат голоса:** WAV 22,05/24 кГц - предложение, не измеренный готовый тракт; расход карты и микширование следует испытать.
6. **Новые языки:** обязательны RU/DE; UK/EN - перспектива, не текущий факт.
7. **Политика тишины:** в V3 ночной режим блокирует только автоматические часы, но таймеры и будильники звучат. В V4 отдельный *silent mode* следует сделать настраиваемым без неожиданного отключения будильника.

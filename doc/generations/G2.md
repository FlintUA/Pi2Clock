# G2 — I2S sound, one SD card, OLED (planned)

G2 is the planned successor of the [G1](G1.md) clock. **Nothing is implemented or measured yet.** This page is the overview; the details are in the documents of the [g2 folder](g2/), structured on 2026-11-23 from the user's G2 document set ([sources](g2/sources/README.md)).

## Decisions

Recorded on 2026-11-23:

- **Two encoders** (TIMER and VOLUME), as in G1. A one-encoder variant is planned only after the two-encoder G2 release.
- **DS3231** is part of the Base build and takes over the DS1302's role with G1 behaviour: local time kept in the RTC, written on manual changes and NTP corrections, running from its backup cell without power.
- **INMP441** is wired on the board; the first G2 release gives it no function except, at most, a capture test ([MICROPHONE.md](g2/MICROPHONE.md)).
- **Base first**; Full options (BME280, battery, weather, microphone functions) later.

- **German timer phrase:** "Timer [N] über [DURATION] ist abgelaufen" ([VOICE.md](g2/VOICE.md#three-timers)).

Still open: the final touch-key mapping, the speech sample rate.

## What changes from G1

| Area | G1 | G2 |
| --- | --- | --- |
| Local sound | DFPlayer Mini with its own card | MAX98357A I2S amplifier fed by the Pico's decoder (PIO I2S on GP16–GP18), 8 Ω 3 W speaker, software mono mix |
| SD cards | Two identical cards (DFPlayer + SPI) | One card on SPI1 with a named `/PI2CLOCK/` layout, long file names, JSON manifests |
| Display | LCD1602 over I2C, backlight on GP6 | OLED SSD1322 3.12" 256×64 on SPI1 (shared with the SD card, own CS/DC/RES) |
| Buttons | Five mechanical buttons, active low | Five TTP223 touch sensors, active high |
| Encoders | Two (TIMER, VOLUME) | Two (decided); a one-encoder variant after the G2 release |
| RTC | DS1302 on GP2/GP4/GP5 | DS3231 on I2C (decided, Base), same role as in G1, about ±2 ppm |
| Indication | — | Four WS2812 through a 74AHCT125 level shifter |
| Timers | One countdown | Three independent timers, announced with number and initial duration |
| Music | Folder 08, tracks 1–255 | Collections (classical, disco, ru_music, …), *All music*, catalog with `track_id` |
| Speech | Numbered RU/DE recordings, gaps in German | Voice packs per language and voice (6 voices × RU/DE planned), templates and tokens |
| Microphone | — | INMP441 wired (shared I2S clocks); capture test only at first |
| Options (Full) | — | BME280 indoor climate, microphone functions, LiPo battery with power path, weather forecast cache |

Kept from G1: alarms with weekdays and snooze, birthdays, player modes, Bluetooth A2DP (with the OTA 25–28 improvements), Wi-Fi Home/Direct, NTP and Europe/Berlin DST, browser control, A/B OTA, settings in Flash. Identity: model **Pi2Clock G2**, build IDs `g2-…`, tags `g2-vX.Y.Z`, OTA target `0x23500202`, development branch `codex/gen2`.

## Firmware architecture (proposal)

```text
Timer / Alarm / Clock / Weather / Settings  (semantic events)
                    |
             Speech planner (language + voice + grammar)
                    |
        Asset resolver (manifest, catalog index)
                    |
        Audio queue (priority, ducking)
                    |
        File system + decoder (MP3/WAV) -> PCM ring
                    |
          +---------+---------+
          |                   |
     PIO I2S              Bluetooth A2DP
     MAX98357A            external speaker
```

New interfaces: `audio_play(path)`, `speech_say(event_id, params)`, `music_play(track_id)`. The file index is built from the manifest and catalog, never from DFPlayer numbers, and is cached so a timer never waits for an SD scan. A missing file means text on the OLED, WS2812 indication and a fallback tone from Flash — never a neighbouring track.

**One code base for G1 and G2.** G2 is best built from the same source tree with a generation option (`CLOCK_GENERATION=G2`) and a hardware layer for audio output (DFPlayer or I2S), display (LCD or OLED), keys (buttons or touch) and RTC (DS1302 or DS3231). The logic (alarms, timers, player, network, page, OTA) stays shared, and G1 fixes reach G2 automatically. The first step is therefore the split of `main.c` from the G1 roadmap: screens and menus are currently written for the 16×2 LCD inside `main.c`.

## Review of the G2 documents (2026-11-23)

The document set is consistent with G1 and realistic in its warnings. Points to settle:

1. **One or two encoders.** The UI concept (13 November) proposed one central encoder; the wiring plan (23 November) keeps two. Decided: two.
2. **Microphone clocks.** If the I2S clocks run permanently at 44.1 kHz (the rate G1 already converts everything to), the INMP441 can share BCLK/WS and record at 44.1 kHz with software decimation to 16 kHz. The MCP23017 variant with separate microphone clocks is then unnecessary.
3. **Speech sample rate.** 22.05 kHz converts to 44.1 kHz by an exact factor of two; 16 or 24 kHz need fractional resampling (available from G1). All work; 22.05 kHz is the simplest.
4. **German timer phrase.** The CSV and the phrase document used different German patterns for `timer.finished`; decided: "über [DURATION]".
5. **Music catalog.** Writing `catalog.json` by hand does not scale; a PC tool that scans the collections, reads ID3 tags and validates the card is proposed.
6. **Twelve voice packs** are a large recording or synthesis effort with licence questions for a kit; start with one validated voice per language, as the documents allow.
7. **New feature areas** not present in G1: weather (needs an Internet weather service, an API key and a cache policy), battery operation, voice notes. They belong to the Full variant and later stages.
8. **SD writes** (logs, recordings, backups) need FatFs with power-loss safety and a write budget; G1 only reads the card.
9. The phrase texts contained stray closing quotation marks and outdated notes ("V3", snooze "not implemented"); the CSV in the repository is cleaned.

## Suggested stages

1. **Decisions and parts:** done on 2026-11-23 (see [Decisions](#decisions)); order the remaining modules.
2. **Bench prototype:** Pico 2 W + MAX98357A + SD + OLED on one SPI bus, DS3231 and the INMP441 wired. Main risk to retire: continuous I2S audio with Wi-Fi, Bluetooth, web server and OLED updates active.
3. **Shared code base:** split `main.c`, introduce the hardware layer; G1 keeps building unchanged.
4. **G2 with G1 functions:** everything G1 does, on I2S, OLED and one card (FatFs with long names, manifest, catalog).
5. **Three timers** and the new speech engine with the first voice per language.
6. **Music collections** and *All music*.
7. **WS2812** notifications (silent mode, timer/alarm pulsing), then the Full options: BME280, microphone functions, battery, weather.
8. **Kit board and enclosure** (KiCad main board with connectors, panel with touch keys) after the prototype has settled.

## Open questions for the prototype

1. Free PIO state machines and DMA channels next to CYW43 (which uses PIO) and the SPI bus.
2. Continuous I2S output while Wi-Fi, Bluetooth and the web server are active; buffer size and CPU load of one decoder serving two outputs.
3. Amplifier supply, speaker impedance and loudness, supply noise, gain setting, `SD/MODE` state of the actual board.
4. Peak RAM with I2S buffers, the PCM ring (64 KiB since G1 OTA 28), the OLED frame buffer (8 KiB) and four web clients.
5. Shared SPI1: SD streaming during OLED redraws.
6. TTP223 behaviour through the panel, start-up calibration, false triggers.
7. Current budget: OLED, SD, WS2812, amplifier; 3V3_OUT limit; USB-C CC and power path.
8. Flash budget: the G1 1.1.0 OTA image is about 927 KB of the 1,536 KiB slot; Cyrillic OLED fonts, FatFs and the speech engine must fit. The browser page can be minified first ([WEB_UI.md](../WEB_UI.md#size)).
9. Migration of settings and audio assets from G1.

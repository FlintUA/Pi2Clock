# G2 — I2S sound with one SD card (planned)

G2 is the planned successor device. Nothing below is implemented or measured yet; it records the agreed direction and the open questions that a hardware prototype must answer before firmware work starts. Current development continues on [G1](G1.md).

## Direction

- **Remove the DFPlayer Mini.** Local sound comes from a **MAX98357A** I2S class-D mono amplifier driven by the Pico.
- **One SD card.** The Pico reads all audio from its SPI microSD card. The same software path (Helix MP3 decoder → PCM buffer) feeds both outputs: I2S through PIO/DMA for the built-in speaker and SBC/A2DP for a Bluetooth speaker. The need to keep two identical cards disappears.
- **Music collections.** Folder-based collections (for example Disco, Classical, Russian music), selectable individually, plus an *All music* selection with shuffled playback across collections that excludes speech, beeps and other system audio. Collection selection stays separate from playback order (sequential, shuffle, repeat-one) and keeps useful Previous/Next history.
- The clock core (DS1302, encoders, buttons), network functions, browser control and OTA updates carry over from G1.
- **Planned additions (user request, 2026-11-21):** a 3.1-inch OLED display (replacing or complementing the LCD1602), WS2812 addressable LEDs and an I2S MEMS microphone (the user named it "MP441"; most likely the INMP441 module). Exact modules, purposes and pins are not decided.
- **Three timers** instead of the single G1 countdown (user plan, 2026-11-20).

## Expected hardware changes

| G1 part | G2 |
| --- | --- |
| DFPlayer Mini + card A, UART0 GP16/GP17, BUSY GP18 | Removed; these three pins become free |
| DFPlayer speaker output | MAX98357A (I2S BCLK, LRCLK, DIN; SD/shutdown and GAIN pins) with its own speaker |
| Card B on SPI1 GP8–GP11 | The only card, holding speech, music and system sounds |

Using the freed GP16–GP18 for BCLK, LRCLK and DIN is a candidate assignment, not a decision.

## Identity

- Model **Pi2Clock G2**, build IDs `g2-…`, tags `g2-vX.Y.Z`, development branch `codex/gen2` (created when work starts).
- OTA target `0x23500202`. G1 and G2 packages are mutually rejected before any Flash erase. The G2 OTA sequence counts independently from G1.

## Open questions for the prototype

1. Free PIO state machines and DMA channels next to CYW43 (which uses PIO) and the SPI card.
2. Continuous I2S output while Wi-Fi, Bluetooth and the web server are active; buffer size and CPU load of one decoder serving two outputs.
3. Amplifier supply, speaker impedance and loudness, power-supply noise and gain setting.
4. Peak RAM with I2S buffers, the PCM ring and four web clients.
5. Settings and audio-asset migration from G1, including the new collection layout.
6. OLED controller and interface (3.1-inch modules commonly use an SSD1322 256×64 controller over SPI) and the pins and frame-buffer RAM it needs.
7. WS2812 timing on a PIO state machine and its power supply; the microphone's I2S input sharing PIO/DMA with the MAX98357A output; what the microphone is used for.
8. Flash budget: the G1 OTA image with the layout v2 page is about 881 KB of the 1,536 KiB slot. If G2 features do not fit, the phone page can be minified first (see [WEB_UI.md](../WEB_UI.md#size)).

# Changelog

## Unreleased

- Manual speech during music and the timer (OTA 31 candidate): time, date and next alarm can be requested while the music player is open or the countdown runs. Bluetooth music pauses and continues from the same position; built-in speaker (DFPlayer) music stops and the same track restarts from the beginning. New request *time left on the timer* (browser Speak sheet, MINUS short while the countdown runs, USB `say-timer`), spoken from existing recordings rounded to the nearest minute (RU hours + minutes; DE minutes below one hour). MODE hold speaks the time during the countdown. New status field `speech_ready`, command `/control say_timer`, results `no_timer` and `no_recording`. OTA 31 wrongly switched German "Minuten" to `17/015`, which on the clock's card is the half-hour double beep (user report 2026-11-26); `17/017` restored. The repository copy `sound/_sdcard/17` still has the older layout (015 = "Minuten", no 017) and must be brought in line with the card.
- Quiet-hours indication (OTA 30 candidate): while quiet hours are in effect the LCD shows `QUIET` at the right of the first row (MUTE still wins), and the clock window of the page shows "Quiet until HH:00" with a hollow dot instead of "Sound on" (also "Announcements paused" when automatic announcements are switched off). New status field `overview.quiet_now`. The quiet-hours summary in Settings is now fully translated ("Тихо с 21:00 до 06:00 (через полночь)." instead of a mixed text). The status reply buffer grows from 4 to 5 KiB, because its worst case with maximal values is about 4.2 KB.
- G2 documentation (2026-11-24): MCP23017 interrupt (INTA open-drain active low on GP21 with 10 kΩ pull-up, register handling), pull-down placement on the main board, battery divider on GP28 after the power switch, Full-variant pin map; outdated "GP6 = OLED reset" in the second review noted.
- G2 documentation (2026-11-24): MCP23017 wiring for the Full variant (touch keys on GPA0–GPA4, address 0x20) with review changes: INTA on the freed GP21 instead of GP5, 100 kΩ pull-downs for detachable keys, unused pins defined; freed GPIOs assigned (microphone clock, GP28 battery ADC).
- G2 documentation (2026-11-24): WS2812 wiring through the 74AHCT125 as specified by the user (channel 1, 330 Ω series resistor, 100 nF decoupling), with handling of the unused channels.
- G2 documentation (2026-11-24): GP6 drives the touch-key backlight with the G1 circuit, GP5 becomes an external alert output (vibration pad or lamp), OLED reset by RC; light-signal rules, effect library and signal dictionary for deaf and hard-of-hearing users with sources (Google Nest, alerting systems, ADA/NFPA, WCAG); phone notifications planned; risk table added to the hardware document.
- G2 documentation (2026-11-23): the user's G2 document set structured into English documents under `doc/generations/g2/` (hardware and wiring, SD layout, speech events RU/DE with a cleaned CSV, UI concept, microphone plan), decisions of 2026-11-23 recorded (two encoders, DS3231 in Base, INMP441 wired without function, Base first), originals kept in `doc/generations/g2/sources/`, SD card skeleton in `sound/g2_sdcard/`; [G2 overview](doc/generations/G2.md) rewritten with a review of the documents and suggested stages.

Basis: OTA 26 blind test on Portable, where power saving off removed the long gaps and bitpool 35 with power saving off removed audible crackling. `wifi-pm auto` and `bt-bitpool 0` select the automatic behaviour. ## 1.0.0-rc.1

First tagged C firmware release candidate for Raspberry Pi Pico 2 W. Existing hardware-tested capabilities include RTC/LCD, encoders, timer, alarms, LOCAL audio, SPI FAT32/MP3 and Bluetooth playback with Portable/Nest.

### Added

- Optional asynchronous Wi-Fi/NTP with Europe/Berlin CET/CEST conversion and RTC correction while idle.
- Local Windows Wi-Fi provisioning helper; settings Flash v8 with backwards reads of v1-v7.
- Firmware version/build ID and updater verification using the selected UF2's build-ID sidecar.
- Build identity distinguishes Bluetooth/MP3/Wi-Fi profiles as well as the source revision.
- Dynamic alarm track selection and v8 track storage through 255.
- Host tests and Windows/Linux GitHub CI.

### Fixed

- Duplicate saved/scanned Bluetooth addresses in the combined UI/command catalog.
- Unknown discovery labels overwriting saved speaker names.
- Preferred connection not being resumed when leaving completed discovery without selecting a new device.
- Serial overflow handling so an overlong command tail is discarded instead of interpreted separately.
- First-boot updater verification now accepts three blank clock settings sectors with a valid Flash layout.

### Validation and release status

This is a prerelease. Host tests cover alarm scheduling, calendar/DST and NTP packet validation, Bluetooth catalog behavior, and v1-v8 Flash migration/CRC/fallback. Firmware profiles are built before tagging. New network/RTC functionality, v8 hardware persistence, updated UI behavior and updater build verification require on-device acceptance before v1.0.0 stable.

After new saves replace both clock settings slots with v8, old v7 firmware cannot read the latest settings. A current -NoWifi build is the compatible offline fallback.

### Deferred

Bluetooth switch-latency optimization and the missing German timer-completion recording remain at the end of the roadmap, in that order. See [ROADMAP.md](doc/ROADMAP.md) for other planned functional milestones.
